# 全站 UI 诊断（基线 2026-10-28）

定型：老项目改造 · 优化 UI（档位待用户选）· 阶段：规范体检与诊断

截图：本目录 01–05，1440×900，开发版屏幕外截取（统计页在开发数据目录里还在扫描，空白，未纳入）。

## 规范体检

| 项 | 现状 | 性质 |
| --- | --- | --- |
| 调性 | 深灰工具台，信息密，等宽数字 | 上游 Code-by-wire 的气质，可留 |
| 字体 | 正文无衬线 + 数值等宽；字号有 `text-meta/aux/body/label/title` 一套刻度，但 fork 新页面另用了 12 种 `text-[0.6875rem]` 之类的随手字号 | 刻度是资产，随手字号是偶然值 |
| 色彩 | 两套变量并存：上游 `ink-*/fg-*`（设置、会话、新建页），fork 新页面 `--ui-text-*/--ui-stroke-*`（右栏、Skill、提示词）；看板另加了青、黄、红、橙四种强调色 | 灰阶是资产；看板的多色是偶然值 |
| 底色 | #0d0d0d 一类深灰 | 用户偏好纯黑（HUD 设置窗口已改 #000） |
| 图标 | lucide 线性图标 | 资产 |

结论：上游规范是好的，问题出在 fork 后加的页面没按它做（看板、右栏、Skill 页）。

## 主要问题（按影响排序）

1. **看板总览太吵**：4 张数字卡 + AI 洞察卡（4 个红/橙描边标签）+ 柱状图 + 环形图同屏，五种颜色抢注意力；「整体进度 53.5%」旁边又有一个 0/4 的环，同一件事说两遍。全应用只有这一页是彩色的。
2. **两套字号和灰阶混用**：右栏「指标」页的标签全部带虚线下划线（输入、输出、缓存读取……每行都有），读起来像一排链接；字号比设置页小一档，中英数字混排参差。
3. **侧栏每行末尾都是同一个橙色 Claude 图标**：几十行重复，没有信息量，反而把「进行中」的状态标记压下去了。
4. **设置卡片标题大小写不一**：「外观」「悬浮条」是普通标题，「CLAUDE 账号」被大写加字距处理成另一种样子。
5. **新建会话页**：「创建」按钮禁用态是灰块，看着像次要按钮；「带远程」的说明文字用了链接蓝。

## 三档

- **整理**：不换样子，只收拢——fork 页面改用上游的 `ink/fg` 变量和字号刻度；看板总览减到 1 个强调色、去掉重复的进度环、洞察标签改成灰底；右栏去掉虚线下划线（说明放到悬停）；侧栏去掉重复的 Claude 图标（只在非 Claude 会话显示）；设置卡标题统一。改动小，风险小。
- **升级（推荐）**：在整理之上重新定两件事——底色改纯黑、面板用两级灰分层；全站只留一个强调色（沿用现有的 accent 琥珀色），状态色只在状态点上出现。看板总览改成「今天该做什么」一列为主、数字卡缩成一行摘要。结构和导航不变。
- **重塑**：重新探索整体方向（比如把看板做成主页、会话列表退到二级），结构会变。成本最高，眼下不建议。
