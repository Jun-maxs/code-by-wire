# 工作看板（2026-10-28）

定型：老项目改造 · 加新功能 · 阶段：实现

## 一句话任务

我同时推着好几条产品线，每条都开了好几个 agent 会话。打开 Code-by-wire 想知道：手上有哪些事、各做到哪、哪些在等我拍板、今天先做什么。

## 用户已定

- 卡片 = 任务，一个任务可以挂多个会话（2026-10-28 用户选）。
- 第一版做齐：看板列视图、总览、AI 洞察侧栏、排期/灵感/日常（用户选）。
- 结构照参考图（小红书「工作看板」三张截图）走。

## Agent 推断（可改）

- 视觉沿用 Code-by-wire 现有设计变量（灰阶 Mono、深色/浅色两套），不引入参考图的薰衣草紫。状态色用现有的：进行中 = working 青、等我决定 = accent 琥珀、已完成 = ok 绿、待办 = idle 灰；P0 用 danger 红点。
- 参考图的「阻塞」列改叫「等我决定」，和产品卡里的「等你决定」对上。
- 入口：左侧栏「统计」上方加「看板」；中栏靠 `BOARD_ID` 标记切页，和统计/设置同一套。
- 数据存 userData 下 `board.json`（任务、灵感、日常、洞察记录、每日容量），不进可重建的 SQLite 索引。
- 剩余工时 = 预估 × (1 − 子任务完成比例)；没有子任务按列算（待办 0%、已完成 100%，其余 0%）。
- 会话状态自动反映到卡片：挂着的会话在跑 → 卡片亮青色运行条，等回复 → 琥珀「等你回复」。不自动挪列。
- 「从主题导入」：读产品卡的「没收尾」「等你决定」生成候选任务，勾选后加入。
- AI 洞察用 `CBW_CLAUDE_LAUNCHER`（rec）跑 `-p --model haiku --tools ""`，环境变量 `WB_DATA` 指向带 `HOOKS_OFF` 的临时目录，避免工作台钩子注入或拦截。每天 21:00 应用开着就自动跑一次，也可手动。

## 页面

| 页 | 内容 |
| --- | --- |
| 总览 | 问候行 + 4 个指标（在办、整体进度、剩余工时、预计全部完成）、AI 洞察摘要、未来 14 天负荷柱图、状态分布、今日聚焦、风险与提醒 |
| 看板 | 四列拖动换状态；筛选 全部/P0/P1/有风险；每列底部快速添加；点卡片开详情抽屉（子任务、挂会话、开新会话） |
| 排期 | 未来 14 天按日分组，每天的需求工时对每日容量；未排期的一栏 |
| 灵感 | 随手记一条，可归主题，一键转成任务 |
| 日常 | 每日习惯打卡，近 14 天格子 + 连续天数 |
| AI 洞察 | 右侧抽屉：分数、一句话、做得不错、风险预警（高中低）、建议；历史记录 |
