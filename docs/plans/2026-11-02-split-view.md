# 分屏：一个窗口里并排看最多 6 个会话

定型：老项目改造 · 加新功能 · 阶段：实现（用户给了做法和参考截图，直接实现）

## 用户要做的事

同时开着几件事时，不用来回点侧栏，一眼看到每个会话在干什么、做到哪一步、哪个在等我，并且能直接在其中任意一个里打字。

## 现状走一遍

同时跟 3 个会话：点侧栏 A → 看终端 → 点 B → 看 → 点 C → 看，再回 A。每看一次 1 次点击 + 1 次整页切换；「哪个在等我」只能看侧栏圆点，「做到哪一步」要展开底部活动栏的待办。记忆负担：另外两个会话刚才停在哪，靠脑子记。

|                         | 点击                | 页面切换 | 决定（其中系统已知）             | 记忆负担        | 回头路 | 寻找与阅读                     |
| ----------------------- | ------------------- | -------- | -------------------------------- | --------------- | ------ | ------------------------------ |
| 现状（巡一遍 3 个会话） | 3                   | 3        | 3（3：先看哪个其实看状态就知道） | 另外 2 个的进度 | 无     | 每个都要展开活动栏才看到待办   |
| 分屏                    | 0（切到分屏后常驻） | 0        | 0                                | 无              | 无     | 每格顶上直接是进度条和当前一步 |

口径：键盘 Ctrl+Tab 也算一次点击。

## 产品习惯（沿用）

- 对象：会话。不引入新对象，「分屏」只是会话的另一种摆法。
- 动作：侧栏点会话 = 打开它。分屏里点会话 = 把它放进分屏（已在里面就只是聚焦）。
- 承载：中间栏。右栏指标、头部会话菜单都跟着「当前格」走，与单屏一样。
- 反馈：原地变化，不弹提示。
- 状态：圆点 + 细条，颜色只在标记上（DESIGN.md）。

## 方案卡

| 字段     | 内容                                                                                                                    |
| -------- | ----------------------------------------------------------------------------------------------------------------------- |
| 立场     | 专用：中间栏换成网格                                                                                                    |
| 入口     | 头部栏最左「单屏 / 分屏」切换（会话页才有）；分屏时旁边「+」加窗口                                                      |
| 步骤     | 点「分屏」→ 当前会话 + 其他在跑的会话自动铺开（最多 6）→ 点任一格就能输入；点侧栏别的会话 = 加进来，满 6 个时替换当前格 |
| 修了什么 | 做决定的地方没有做决定要用的信息：进度和「等你」直接画在每格顶上                                                        |
| 拿到什么 | 每格：顶部 3px 进度条（待办完成比例；没有待办而挂了看板任务时用看板子任务）、状态圆点、标题、当前在做的一步、完成数     |

## 布局与交互细则

- 列数按个数：1→1、2→2、3→3、4→2×2、5/6→3×2；中间栏窄时每格至少约 340px，放不下就减列。网格剩下的空位放「加入一个会话」列表。
- 进度条颜色：等你 = 琥珀，进行中 = 青，全部完成 = 绿，其余中性灰。
- 当前格：标题栏底色略亮、标题用一级文字；终端只在当前格自动聚焦。
- 每格标题栏按钮：终端 ⇄ 记录、单屏查看、移出分屏（只剩 1 格时不能移出）。
- 分屏状态（模式 + 哪些会话）存 localStorage `cbw.splitView.v1`，重启后恢复。
- 头部在分屏时隐藏同主题标签和右侧「Claude Code / 记录」切换（每格自己有）。

## 第二轮（同日，用户追加）

用户问：「分屏是可以直接打字输入的会话不？」——是。每格就是该会话真正的终端，点一下就能输入（已用屏幕外开发版验证：点格子后焦点在该格的 xterm 输入框，输入的字出现在 Claude Code 提示符后，截图 `13-typing.png`）。不在本应用里运行的会话显示记录和「恢复」。

用户又要：

1. 悬停看任务：已完成 / 正在进行 / 待执行。本机会话不写待办（`tasks/` 目录全空），所以「任务」取用户发出的每条指令：主进程 `src/main/turn-activity.ts` 增量读会话记录（首次读末尾 1 MB，当前任务更早时整读一次，之后只读新增字节），得到最近 20 条指令（步数、起止时间）、中途追加的消息（`queued_command` 附件）和还在排队的消息（`queue-operation` 的 enqueue/dequeue/remove/popAll）。有待办时一并归组。
2. 移出窗口不删会话：× 本来就只移出分屏，提示改为「移出分屏（不删会话）」。
3. 新增新会话窗口：「+」弹层和空位列表顶上加「新建会话 · <目录名>」，在当前格的文件夹用当前格的智能体新建，直接进分屏（满 6 格时替换当前格）。
